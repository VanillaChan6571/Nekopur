# Nekopur 26.3 port

This branch combines Nekopur's `ver/26.2` features at `cb1413710` with
Purpur's `ver/26.3` at `9de5ecbaa`, updated to Paper `dev/26.3` at
`ace932ed4e72bc7843cc4af1fa877da4ca8b2f1e`. The Minecraft target is the
**26.3 release**, protocol **777**. Paper itself still labels this development
branch ALPHA. The Paper pin is in `gradle.properties`.

The earlier RC3 jar used snapshot protocol `1073742162`, so its normal login
version check rejected released 26.3 clients. This update uses the release
Minecraft sources and version metadata; it does not bypass the login check.

## Patch layout

Nekopur's async world, discovery, handoff, movement-grace, unsigned-chat delivery,
and arrival hooks are retained in
`purpur-server/minecraft-patches/features/0022-Port-Nekopur-hooks-and-repair-Purpur-APIs-for-26.3.patch`.
The old standalone `PrepareSpawnTask` file patch is incorporated into this feature
patch. The feature also adapts Purpur calls to changed Minecraft APIs.

`purpur-server/paper-patches/features/0005-Adapt-Purpur-runtime-APIs-to-Minecraft-26.3.patch`
contains the corresponding CraftBukkit adaptations. Both patches were exported
from commits in the generated repositories; source edits alone are not deliverables.

26.3 teleport acknowledgements contain a client position. They now respect the
handoff source freeze, as ordinary movement packets already did. The destination's
one-shot prediction allowance remains shared by the moved-too-quickly and
moved-wrongly checks, with the existing distance bound and configuration gates.

Minecraft replaced the global fuel table with item components. `FuelOverrides`
preserves `Server.addFuel` and `Server.removeFuel` for furnace burning, insertion,
and Bukkit fuel queries without modifying item stacks. Spawner item data is applied
after the new static block-entity component setup.

## Build and verification

Use JDK 25 and run from this branch's checkout:

```powershell
$env:JAVA_HOME = 'C:\Java\jdk-25.0.3'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
.\gradlew.bat applyAllPatches --no-daemon
.\gradlew.bat :nekopur-server:createNekopurMojmapBundlerJar --no-daemon
.\gradlew.bat :purpur-server:test --tests org.nekopur.network.NekopurrNetworkTestSuite --tests org.nekopur.compat.FuelOverridesTestSuite --no-daemon
```

If Windows reports `Unable to establish loopback connection`, set
`JAVA_TOOL_OPTIONS` to `-Djdk.net.unixdomain.tmpdir=<an absolute nonexistent directory>`
before invoking Gradle. Keep that directory absent so Java falls back to TCP.

The server artifact is
`nekopur-server/build/libs/nekopur-bundler-26.3.local-SNAPSHOT-mojmap.jar`.

Verified locally with JDK 25.0.3: full patch application against the release,
bundler build, and all 38 tests in the two suites above. `ReleaseProtocolTest`
checks the version metadata used by the login handler and the compiled protocol:
both must identify release 26.3 and protocol 777, not RC3's snapshot protocol.

## Runtime checks still needed

- Async world creation, spawn preparation, pool refill, and unload on a test server;
  see [the async world API](ASYNC_WORLD_API.md).
- Paired Purroxy handoffs: frozen source movement, preserved entity ID, bounded
  arrival prediction, chat continuity, effects cleanup, and Citizens refresh.
- Silk-touch spawner placement and custom fuel behavior in regular furnaces,
  smokers, and blast furnaces.

Upstream's remaining development-branch limitations are listed in
[`MC_UPDATE_TODO.txt`](../MC_UPDATE_TODO.txt). In particular, villager lobotomization
is unapplied upstream, so `Villager.isLobotomized()` reports false. This port does
not claim to qualify this development build for production or add 26.3 protocol
support to Purroxy.
