# Native Neko world generation

The `nekopur:neko` world preset combines Tectonic terrain with an ocean-biased
continental layout. It is implemented in Java inside Nekopur. There is no
external worldgen datapack to install and no runtime JSON terrain parser.

## Native Nether overhaul

For a **new world**, select one of these presets in `server.properties`:

```properties
level-type=neko-mmo-nether-tall
```

This retains the Neko MMO Tall Overworld and adds the native Nether overhaul.
`level-type=neko-nether` instead uses the standard Neko Overworld. Their full
registry names are `nekopur:neko-mmo-nether-tall` and `nekopur:neko-nether`.
The original `neko` and `neko-mmo-tall` presets retain their original Nether.
The End is unchanged in both new presets.

| Native biome | Ground and features |
| --- | --- |
| `nekopur:ashen_barrens` | Basalt, blackstone, gravel, short basalt stumps and ash ambience |
| `nekopur:ember_grove` | Crimson nylium, magma patches, crimson fungi, weeping vines and hoglins |
| `nekopur:soulwood_hollow` | Soul soil/sand, warped nylium patches, warped fungi, vines and bone spires |
| `nekopur:obsidian_shores` | Blackstone, obsidian near the lava surface, obsidian deposits and basalt ceilings |

The four custom regions dominate the climate selection, with smaller regions
of all five vanilla Nether biomes retained. Placement uses the seeded vanilla
Nether temperature/humidity fields; it does not randomly replace individual
chunks. Biomes use vanilla blocks, mobs, sounds, particles and feature codecs.
Their registry data is synchronized to vanilla clients without a client mod.

The vanilla Nether dimension type and terrain router remain intact: build
height 256, logical/generation height 128, bedrock floor/roof, lava level 32,
8:1 portal coordinate scale and ordinary Nether mob behavior. Custom surface
rules run behind the original bedrock rules. Ores, ancient debris and carvers
keep vanilla placement. Fortresses and ruined portals can appear in all four
new biomes; bastions appear outside Ashen Barrens, and fossils can appear in
Ashen Barrens and Soulwood Hollow.

Existing worlds retain the generator stored in their world data. Changing
`level-type` does not convert their saved Nether. No existing world is migrated
or regenerated by this feature. Native `/nekolod` terrain previews currently
support the Overworld, not this Nether generator; generated-chunk LODs are a
separate path.

Validation on 2026-10-12 passed all 61 worldgen tests, including seven Nether
checks for preset isolation and aliases, client/saved-world codecs, structure
tags, feature ordering and unchanged raw terrain columns. Sampling 49,152
positions at Y=64 across three seeds found custom coverage of 60.85%, 62.06%
and 63.25%; all nine biomes appeared. These are sampled results, not guaranteed
worldwide percentages for every seed.

An isolated server generated and saved native Nether terrain on seed
6449995202838594431. Inspection of 36 chunk snapshots in four biome
neighborhoods found the expected surfaces, ores, fungi/vines and bone spires,
with bedrock at Y=0 and Y=127. Generation also creates neighboring dependency
chunks. Ordinary vanilla mushroom decoration can place mushrooms on top of
the roof at Y=128; no expanded terrain volume is introduced. Client registry
codecs were tested, and the saved generator and inspected palettes survived
server restart. Connected-client visual acceptance remains an in-game check.

## Native distant surface previews

Nekopur includes a bounded, asynchronous coarse preview service for saved native
Neko and Neko MMO Tall worlds. It samples the saved generator's preliminary
surface graph, biome source and sea level without loading or generating playable
chunks. A tile contains 64 by 64 estimated surfaces; detail levels 7 through 10
sample at strides 2, 4, 8 and 16 and span 128, 256, 512 and 1,024 blocks.
These estimates omit final density detail, caves, exact aquifers, trees and
structures. Heights and biome cover can differ from finished terrain.

The matching NekoDistantHorizons adapter delivers these results using DH 3.3's
coarse LOD protocol and marks them as completed SURFACE previews. Actual detailed chunk
snapshots retain their stronger LIGHT generation status. Install both updated
server and adapter jars. Native sampling and commands work without the adapter;
DH network delivery requires it. No seed or custom world generator is required
on the client.

The built-in `/nekolod` command requires `bukkit.command.nekolod` (operator by
default). Coordinates are block coordinates; prewarm radius is in chunks.

| Command | Behavior |
|---|---|
| `/nekolod status [world]` | Native cache, worker load, built tiles, cache hits, pending requests and prewarm progress |
| `/nekolod sample <world> <x> <z> <detail>` | Build/cache one aligned coarse tile and report its timing |
| `/nekolod prewarm [world] <x> <z> <radius-chunks> [detail] [accurate] [allowUpgrade]` | Cache nearest tiles first; accurate mode samples final terrain immediately, while allowUpgrade alone estimates first then refines; defaults to detail 10 |
| `/nekolod cancel` | Stop prewarm work and revoke all session refinement regions; completed cache entries remain |
| `/nekolod pause` / `/nekolod resume` | Temporarily control coarse sampling and new coarse delivery; detailed terrain remains available |
| `/nekolod enable [world]` / `/nekolod disable [world]` | Persist per-world coarse controls in the active Purpur configuration |
| `/nekolod clear [world]` | Clear native in-memory tiles for that world; the adapter's encoded SQLite cache is separate |

For example, `/nekolod prewarm world 0 0 128 10` warms a 2,048-block radius.
Jobs submit nearest tiles first with an in-flight window equal to the selected
worker pool size, accept radius 1 through 512 and at most 1,024 tiles, and stop on cancellation, unload or error. The memory cache evicts old
tiles when full; prewarming more tiles than its capacity does not retain all of
them. Two preview workers, two accurate/upgrade workers, 64-task queues and
128 cached tiles are the defaults. Both worker counts accept 1 through 8;
`upgrade-workers` defaults to the configured `workers` value when omitted.
Prewarm does not fill either queue with the whole region. Requests can finish
out of order; the fast-to-upgrade transition waits for every fast tile. All
job state, progress, and accurate cache publication stay on the primary thread.
Each sampling worker owns its sampler/context. Cancel stops refills and ignores
late job callbacks; active sampling can finish before its result is invalidated.
Requests for the same tile share work. World unload releases native state;
server shutdown cancels queued work and stops the workers.

### Accurate initial prewarm

With the updated native server and DH adapter 0.16.4, use:

```text
/nekolod prewarm world 0 0 256 10 accurate
```

Players may omit the world name. This samples final native base terrain density
and aquifers immediately, using the configured bounded accurate-worker pool without creating
playable chunks. It skips the preliminary estimate pass. The same area requires
accurate samples for requested details 7 through 10 throughout this server
session, including old rough SQLite entries and requests after native memory
eviction. Previously corrected SQLite entries can be served immediately.
`accurate` implies refinement authorization; adding `allowUpgrade` is optional.

The console reports accurate-mode progress about every ten seconds as tiles
finish. Status and completion distinguish new samples from native accurate cache
reuse. Cold sampling takes substantially longer than the estimate pass; a repeat
command can still finish quickly when accurate tiles are cached. Duration alone
does not measure quality. Detail 10 samples every 16 blocks, so small features
between samples can be missed even when the sample heights and water are accurate.
Biome cover remains approximate; trees, structures, surface rules and old-chunk
blending are omitted. Region authorization is session state: rerun the command
after restart. Keep existing server and client caches.

Accurate-first validation passed all 43 native tests and 69 adapter tests. An
isolated saved tall world sampled a cold tile in 3,560 ms and reused it in 7 ms
on a second command, correctly reporting one reused accurate tile. Old rough
SQLite data and cold detail-9 requests returned accurate data first. Checked
heights, fluids and biomes matched native columns; accurate mode queued no
preliminary sampling and generated no gameplay chunks. Accurate SQLite data
survived native cache clearing. Timings are local samples, and connected-client
visual rendering still needs an in-game check.

### Fast initial prewarm with later refinement

With the updated DH adapter, players can also run:

```text
/nekolod prewarm 0 0 256 10 allowUpgrade
```

Console must name the world: `/nekolod prewarm world 0 0 256 10 allowUpgrade`.
This covers 64 detail-10 tiles. The fast pass completes first; a separate bounded
accurate-worker pool then samples final native density and aquifers at the same
4,096 cell centers per tile. Detail 10 retains its 16-block stride and tile
footprint: upgrading improves accuracy rather than increasing horizontal resolution.
Corrected heights, water and altitude-dependent biomes replace native cached
estimates. Surface materials remain approximate; trees, structures, surface-rule
detail and old-chunk blending require authoritative detailed chunk updates.
Gameplay chunks are not generated by either pass.

`allowUpgrade` also registers the complete prewarm tile footprint as a session
refinement region. Client-requested tiles at any detail from 7 through 10 that
intersect this footprint can receive accurate upgrades at their own detail; a
detail-10 prewarm therefore also refines requested detail-7, -8 and -9 tiles.
This authorization survives job completion and native cache eviction. The
adapter sends fast terrain first, then submits bounded, deduplicated refinement
work. Up to 128 most recently registered rectangles are retained across loaded
worlds. Region overlap does not enlarge authorization outside their union.
Pause preserves regions; cancel revokes all regions and outstanding accurate
work. Clear, disable and unload revoke that world's regions, while shutdown
removes them all. Registrations are session state and do not survive restart.

The adapter replaces each corrected tile in its SQLite cache and sends a DH
partial update to connected clients that requested that tile and remain in range.
The upgrade payload survives native memory eviction. Accurate native cache hits
replay the update, allowing another `allowUpgrade` run to refresh the adapter.
Use `/nekolod status` to see upgrades, refinement regions and worker load;
`/nekolod cancel` stops submissions and revokes session refinement. Pause, clear, disable,
unload and shutdown invalidate outstanding upgrades. Jobs are not resumed across
restarts. The encoded SQLite cache retains completed corrections across restarts.

Native tests measured 2.8 to 5.7 seconds per accurate 1,024-block tile, with
sampled height/fluid/biome comparisons against native columns in both presets.
These local measurements are terrain- and hardware-dependent; the accurate
second pass is more expensive than the preliminary estimate.

All 38 native worldgen tests passed, including cross-detail refinement region
coverage, world scoping, bounded registration and revocation. The earlier
adapter validation passed 58 tests. An isolated saved tall world
with the final jars upgraded one tile in 3.4 seconds, replaced the transport
payload (2,805 to 9,053 bytes), matched native heights and biomes at checked
centers, and left all 4,096 covered chunk positions ungenerated. Command
completion, cancel, callback thread ownership and immediate clear cancellation
passed. Connected-client visual refinement still needs an in-game check.

`upgrade-workers: 4` under `nekopur.lod-preview` in `purpur.yml`, then restart.
The prewarm command is unchanged. `/nekolod status` reports both pool limits,
active/queued work and the prewarm in-flight window. Progress includes percent

## Create a world

Set this before creating the world:

```properties
level-type=Neko
```

`neko` and `nekopur:neko` select the same preset. The preset replaces the
Overworld generator; the normal preset's Nether and End are retained. It uses
the modern Overworld biome source, structures and world height (-64 to 319),
with sea level 63.

This setting selects the generator for a new world. It does not convert existing
chunks. A saved Neko world retains its named noise-settings reference on reload.
Keep using a Nekopur build that includes this preset to open that world.

## Tall MMO preset

For a new world with taller mountains and deeper oceans, select:

```properties
level-type=neko-mmo-tall
```

The explicit registry name is `nekopur:neko-mmo-tall`. The alias is
case-insensitive. This is a separate preset; `Neko` retains its original profile.

| Setting | Neko | Neko MMO Tall |
|---|---:|---:|
| Minimum block Y | -64 | -128 |
| Maximum block Y | 319 | 511 |
| Sea level | 63 | 63 |
| Tectonic mountain vertical scale | 1.125 | 2.0 |
| Ocean depth parameter | -0.22 | -0.35 |
| Deep ocean depth parameter | -0.45 | -0.95 |

The tall profile extends the bottom density fade to -128/-112 and the top fade
to 482/502, increases the terrain-offset clamp to -1.2/3.3, and extends the
preliminary surface search. These changes shape terrain into the extra space;
the build ceiling is not a promised mountain height. Both profiles share noise
keys and horizontal geography, but use separate density graphs and noise
settings. The tall density keys live under `nekopur:tectonic_tall/`.

The Overworld dimension has 640 blocks of vertical space and logical height.
Its sky, lighting, clocks and environmental attributes follow the normal
Overworld. Nether and End stay normal. Surface rules retain their dynamic bottom
anchors, placing bedrock at the new bottom. Native caves and aquifers run across
the larger noise range. The tall profile's global lava floor is -118, instead of
-54, so deep ocean water can extend below the old lava level. Vanilla structure and ore placement rules are retained;
this does not redistribute all ores into the added depth. Larger bounds can
increase generation work and chunk storage. Use a new world folder; changing
`level-type` does not migrate an existing world's saved dimension or chunks.

The tall profile moves the Deep Dark biome-depth transition into the lower
caves. Its climate-depth ceiling rises smoothly from 0.8 at Y=-32 to 1.3 at
Y=-96, instead of Tectonic's original step at Y=32. Deep Dark is favored toward
Y=-70 and below, subject to the other climate parameters. Lush, dripstone and
sulfur cave selection retains its existing climate rules. The same adjusted
depth controls Deep Dark aquifer dryness; terrain and cave density themselves
retain their original functions. Standard Neko is unchanged. This affects newly
generated chunks, not the biomes already saved in existing chunks.

Tall-profile monuments use the median ocean-floor height sampled at nine points
across their 58-block footprint, bounded above by sea level minus 24 and below by
minimum Y plus 8. Their existing foundation supports reach uneven ground. Room
coordinates are constructed at the selected height, and saved monuments retain
that height when their rooms are reconstructed after loading. Standard monuments
keep their original Y=39 base. Existing structures are not moved.

For the tall preset, the default Ancient City start anchor moves from -27 to
-91, and the default Trial Chamber start range moves from -40/-20 to -104/-84.
These are start anchors, not the lowest floors of the assembled structures;
normal jigsaw dimension-bound checks remain active. Only the named built-in
structures with their original absolute height providers are adjusted. Custom
providers and surface-projected structures retain their configured heights.
Shipwrecks and ocean ruins already follow the ocean-floor height; mineshafts and
strongholds already use the generator's minimum Y.

The tall profile now doubles the horizontal wavelength of temperature and
humidity **for biome selection only**. Continentalness, erosion, depth,
weirdness and all terrain density functions retain their existing samplers.
This broadens warm/cool and dry/humid surface regions without changing the
Tectonic terrain height, continental geography or the amplified vertical range.
It is not a change to the generator's terrain noise scale.

Dappled Forest can replace ordinary Forest, Savanna and Savanna Plateau. Pale
Garden can replace Dark Forest. A shifted, seeded humidity field with four
times the original horizontal wavelength selects broad territories: nonnegative
values select Dappled candidates and values at least -0.08 select Pale Garden
candidates. The shift separates the territory selector from the local dry
savanna/humid dark forest climate windows. Acacia and dark oak regions remain;
there is no fixed replacement percentage for every seed. Windswept Savanna is
not a Dappled replacement candidate. Elevation and erosion can still break up
forest regions along mountains, coasts and other terrain boundaries.

The native `nekopur:forest_regions` source retains exact original ocean, river
and underground biome selection, and rejects broadened climate results that
would introduce a new water or cave biome. Other surface biome positions can
change with the broader temperature/humidity fields. Both scalar preview and
bulk chunk resolvers use the same selection rules and per-resolver contexts.
Original and broadened lookups own separate climate search indexes: Minecraft
caches the previous nearest biome leaf, so sharing one index can affect tied
water/cave results. The additional index is constructed once per source instance
and rebuilt on codec load, not on every chunk.
The save codec still stores the underlying source and existing vanilla biome
holders. Already saved forest-region sources are not wrapped again. Tall worlds
saved with the older named vanilla Overworld source adapt when their generator
loads; custom/direct biome sources are retained. Standard Neko keeps its biome
layout. Reopening a saved tall world requires a Nekopur build containing its
native biome-source codec. Only newly generated chunks receive this layout;
saved chunks retain their existing biomes. Native seed previews sample the new
layout, but previously persisted DH LODs retain their old biome data until rebuilt.


## Terrain and provenance

`TectonicTerrainFactory` constructs the terrain graph using Minecraft's Java
noise, spline, density and aquifer implementations. The conversion input is
Apollo's Tectonic **3.0.29 datapack release for Minecraft 26.3**; the datapack is
only a development input, not a runtime dependency. See the source attribution
and license shipped alongside the factory.

`NekoGeography` applies an additional ocean bias to Tectonic's ocean-offset
constant before the continent-dependent terrain and biome functions are built.
The result is a modern continental generator inspired by the older large-ocean
layout, not the exact Minecraft 1.6.4 generator. Ocean coverage varies by seed.

Native density functions and noises are registered under `nekopur:tectonic/`.
Vanilla registry entries are not replaced. Noise keys participate in seed
hashing, so a Neko world will not reproduce Tectonic's original terrain for the
same seed. The generation profile is currently fixed in source; changing its
constants changes future terrain and can create seams in an existing world.

The conversion script, `scripts/generate-tectonic-native.py`, verifies the pinned
input's hash and reproduces the Java factory. Rebuilding the server itself does
not download or convert upstream terrain definitions.
The converter applies `scripts/tectonic_native_profiles.py` to retain both native
profiles when regenerating the factory.

## Threading

The preset uses `NoiseBasedChunkGenerator` and Paper's existing chunk-generation
workers. Immutable terrain graphs are compiled through Minecraft's normal
density-function compiler. Mutable sampling contexts belong to each generation
operation. There is no extra tick loop, custom executor, or main-thread block
placement pass for Neko terrain.

This integration does not claim a speed improvement over the equivalent worldgen
datapack. Terrain complexity, generation demand and the server's worker settings
still determine performance. Pregeneration and profiling remain useful for a
large survival server.

## Seed preview tool

From this checkout, start the live viewer with JDK 25:

```powershell
.\scripts\preview-seed.ps1 -Seed 6571
```

Wait for the ready message, then open `http://127.0.0.1:8765`. Keep the terminal
running; Ctrl+C stops the viewer. Enter numeric or text seeds, generate random
seeds, drag or use arrow keys to pan, and scroll or use the zoom buttons to
explore. Navigation requests new terrain from the native Neko generator. The
coordinate form jumps to another area; terrain, elevation and biome layers
share the same sampled frame. The URL hash preserves the seed and view for
bookmarks. PNG and JSON downloads export the current sampled square.

The local service loads native registries once, uses four sampling workers by
default, and caches eight completed frames and four seed states. Only one frame
is sampled at a time. A cancelled browser request lets that bounded frame finish
before the next request runs. Fast frames use 256 samples per axis; detailed
frames use 128. Sampling spacing adapts to zoom, up to 4,096 blocks per sample.

The service binds only to `127.0.0.1`; seeds are not uploaded elsewhere. It needs
no Minecraft server, world folder, EULA change or additional worldgen datapack.
First-time dependency resolution may require internet access. Existing generated
sources/caches are reused. `-Port` selects another local port, and `-Seed`, `-X`,
`-Z` and `-Mode` set the initial view. `-Threads` selects 1Ã¢â‚¬â€œ32 workers; `-JavaHome`
selects JDK 25.

The initial overview spans approximately 32,768 blocks centered on X/Z 0;
sample spacing depends on the browser viewport. North is up. The origin cross
marks coordinates 0/0, not the world's spawn. Start at a different area:

```powershell
.\scripts\preview-seed.ps1 -Seed 'neko islands' -X 10000 -Z -5000
```

Numeric and text seeds use Minecraft's `WorldOptions.parseSeed`; the resolved
numeric seed is shown and preserved exactly, even beyond JavaScript's safe
integer range. Blank seeds are rejected to avoid accidental random previews.
For a standalone static export, add `-Export`:

```powershell
.\scripts\preview-seed.ps1 -Export -Seed 6571 -Size 256 -Step 128
.\scripts\preview-seed.ps1 -Export -Seed 'neko islands' -Mode detailed -Size 128 -Step 16
```

This writes a self-contained `index.html`, three PNG maps and `samples.json`
under `seed-previews/`. The exported page explores its precomputed square.
`-Size`, `-Step` and `-Output` apply only to exports. Relative output paths resolve
from the checkout. Identical seed, bounds, resolution and mode overwrite the
same export directory; different settings create separate directories.

Fast mode samples Tectonic's preliminary surface-height density function from
the native registry. It estimates elevations and coastlines before final
density/caves/aquifers. Detailed mode samples the actual solid noise-column
height (`OCEAN_FLOOR_WG`, minus one), including underwater ground. It is slower;
use a smaller area to inspect promising seeds. Water coloring means ground
below sea surface, not a guarantee that every sampled depression contains water.

Both modes sample the native Overworld biome source at ground or sea-surface
height, using quart coordinates without final block-biome zoom. They omit
structure terrain adjustments, trees, surface decoration, and structure
placement. Small features between samples can be missed. Biome percentages
describe sampled points, not exact whole-world coverage. Use the same source
profile/build when comparing with a server; changing the native terrain code
changes previews and newly generated chunks.

The Gradle equivalents (also usable on other operating systems with JDK 25) are:

```text
./gradlew :nekopur-server:seedViewer -Ppreview.seed=6571 --no-daemon
./gradlew :nekopur-server:previewSeed -Ppreview.seed=6571 -Ppreview.size=256 -Ppreview.step=128 --no-daemon
```

## Accurate sparse sampling batches (2026-10-12)
